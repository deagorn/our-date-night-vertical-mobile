# ♡ Наше ідеальне побачення

Мобільний сайт у стилі романтичного застосунку: 7 ідей, 2 великі картки одна під одною, турнір та фінальний топ-3.
Працює на GitHub Pages без React, npm, бази даних і платного хостингу.

## 1. Редагування у Visual Studio Code

Відкрийте розпаковану папку сайту у Visual Studio Code.

У файлі `script.js` знайдіть на початку:

```js
const RECIPIENT_EMAIL = "";
const IDEAS = [ ... ];
```

- `RECIPIENT_EMAIL` — **ваша** електронна адреса для результатів (наприклад `"name@gmail.com"`).
- Після останнього вибору сайт **без натискання будь-яких кнопок** відправляє топ-3 на вказану адресу.
- `title` — назва ідеї (усі 7 уже заповнені).
- `description` — повний опис під фотографією (вже заповнений). На телефоні він спочатку скорочений до трьох рядків; для повного тексту натисніть **«Читати повністю»**.
- `image` — шлях до фото, наприклад `"assets/idea-1.jpg"`.
- `emoji` — декоративна заглушка, якщо фото не вказане.

### Де додавати фотографії

**Нічого змінювати у HTML та CSS не потрібно.** Покладіть свої сім фото в папку `assets/` і назвіть їх так: `idea-1.jpg`, `idea-2.jpg`, `idea-3.jpg`, `idea-4.jpg`, `idea-5.jpg`, `idea-6.jpg`, `idea-7.jpg`. Порядок той самий, що у списку `IDEAS` в `script.js` (від вина та сиру до Roblox). У коді шляхи вже заповнені.

Якщо фото мають інше розширення (наприклад, `idea-1.png` або `idea-1.webp`), змініть відповідне `image: "assets/idea-1.jpg"` у `script.js` на фактичне розширення. Назви чутливі до великих/малих літер. Якщо фото ще немає, сайт покаже кольорову заглушку з емодзі.

### Приклад однієї ідеї

```js
{ id: 1, title: "Вечір вина, сиру та кіно", description: "Створюємо атмосферу маленького домашнього кінотеатру...", image: "assets/idea-1.jpg", emoji: "🍷" },
```

Покладіть свої зображення в папку `assets`. Можна використати JPG, PNG або WEBP. Назви файлів і розширення мають **точно** збігатися з `image` у `script.js`. Рекомендовані горизонтальні фото у пропорції 16:9 (наприклад 1600×900): вони відображаються на всю ширину картки. Знімок не обрізається (`object-fit: contain`). Інші пропорції теж відображаються повністю, але можуть з’явитися поля по краях. Якщо фото немає, залиште `image: ""` — відобразиться кольорова заглушка.

## 2. Перевірка на комп'ютері

Просто відкрийте `index.html` у браузері або використайте розширення **Live Server** у VS Code.

- На телефоні дві великі картки розташовані вертикально: перша зверху, друга знизу. Прокрутіть сторінку, щоб побачити обидві.
- Натисніть «Обираю» під бажаною карткою. Свайп для голосування відключено, щоб не помилитися під час прокручування.
- «Пропустити поки що» **відкладає пару** до кінця раунду, але не виключає її з турніру.
- «Назад» скасовує останній вибір, включно з переходом до наступного раунду.
- Прогрес зберігається локально у браузері (`localStorage`).

## 3. Як працює турнір

1. Випадково перемішуються 7 ідей.
2. Одна випадкова ідея автоматично переходить до півфіналу (бо ідей непарна кількість).
3. Перший раунд: 3 пари → 3 переможці.
4. Півфінал: 4 учасники → 2 фіналісти + 2 претенденти на бронзу.
5. Фінал визначає перше й друге місця.
6. Додатковий матч визначає третє місце.

**Разом: 7 голосувань для топ-3.** При повторному запуску пари перемішуються по-новому.

## 4. Автоматичні листи з результатами

GitHub Pages — статичний хостинг без сервера для email. Тому сайт використовує безкоштовний сторонній сервіс [FormSubmit](https://formsubmit.co/).

1. Впишіть адресу в `RECIPIENT_EMAIL` у `script.js`.
2. Опублікуйте сайт через HTTPS на GitHub Pages.
3. Пройдіть тестовий турнір: одразу після 7-го вибору сайт автоматично відправить результат.
4. Сервіс FormSubmit може надіслати на вашу пошту запит підтвердження адреси. Підтвердіть його.
5. Після підтвердження пройдіть новий тест. Відтепер результати мають надходити автоматично, за умови доступності сервісу.

Сайт **не може гарантувати доставку** електронної пошти: це залежить від стороннього сервісу, підтвердження адреси, інтернету й спам-фільтра. Після останнього вибору запит на відправлення починається одразу, а на екрані з'являється статус. Повторного автоматичного надсилання під час оновлення сторінки немає (щоб не створювати дублікати). Якщо запит не вдався, на екрані залишається кнопка **«Скопіювати результат»** — можна переслати вручну. Якщо сторінку закрити під час надсилання, підтвердження доставки може бути недоступним.

**Приватність:** на публічному GitHub Pages адреса у JavaScript є видимою кожному відвідувачу, бо це статичний сайт. Використовуйте адресу, яку не шкода опублікувати, або налаштуйте окрему пошту для результатів. Не додавайте паролі / ключі до коду. FormSubmit отримуватиме текст результатів для їх пересилання.

## 5. Безкоштовна публікація на GitHub Pages

1. Створіть **публічний репозиторій** на GitHub, наприклад `our-date-night`.
2. Завантажте **вміст розпакованої папки** у корінь репозиторію: `index.html`, `style.css`, `script.js`, `assets/` та `README.md`. Файл `index.html` повинен лежати в корені, не всередині додаткової папки.
3. На GitHub перейдіть **Settings → Pages**.
4. У **Build and deployment → Source** виберіть **Deploy from a branch**.
5. Виберіть **main**, папку **/(root)** та натисніть **Save**.
6. GitHub покаже публічне посилання виду `https://username.github.io/our-date-night/`.
7. Перевірте сайт з телефона та зробіть тестове надсилання пошти.

Якщо фото не відображаються, перевірте регістр букв і шлях файлу — GitHub Pages чутливий до регістру.
